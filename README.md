# DRA website

Статический сайт сообщества DRA / Dual Recovery Anonymous для домена `draonline.ru`.

## Стек

- HTML
- CSS
- JavaScript
- JSON
- Cloudflare Pages
- Pages CMS

## Структура

- `index.html` — главная страница
- `about.html` — о сообществе
- `schedule.html` — расписание
- `groups.html` — общая страница групп
- `put-domoy.html` — группа «Путь домой»
- `group-129.html` — группа «129»
- `steps.html` — 12 шагов DRA
- `speakers.html` — спикерские
- `materials.html` — материалы
- `daily-reflections.html` — ежедневные размышления
- `contacts.html` — контакты
- `assets/` — стили, скрипты, изображения, аудио и другие публичные файлы
- `data/` — редактируемые JSON-данные сайта

## Локальный просмотр

Запустите сайт через локальный HTTP-сервер, чтобы корректно загружались JSON-файлы:

```bash
python3 -m http.server 8080
```

Откройте:

```text
http://localhost:8080/
```

## Редактирование контента

Основной контент лежит в JSON-файлах:

- `data/site.json` — название, описание, контакты, социальные ссылки, дисклеймер
- `data/navigation.json` — пункты шапки сайта и вложенные пункты меню
- `data/pages.json` — тексты главной, страниц «О нас», «Группы», «Материалы», «Спикерские», «Контакты»
- `data/schedule.json` — расписание собраний
- `data/groups.json` — карточки, страницы групп, заметки и новости групп
- `data/materials.json` — материалы и ссылки
- `data/daily-reflections.json` — ежедневные размышления
- `data/speaker-recordings.json` — спикерские записи
- `data/steps.json` — 12 шагов

## Ежедневные размышления

Ежедневные размышления редактируются через Pages CMS в разделе «Ежедневные размышления». Данные хранятся в `data/daily-reflections.json`.

Формат даты для каждой записи:

```text
MM-DD
```

Например, для 9 июля:

```text
07-09
```

## Спикерские аудио

Спикерские редактируются через Pages CMS в разделе «Спикерские». Поле «Загрузить аудиофайл» загружает файл в папку:

```text
assets/audio/speakers/
```

После загрузки Pages CMS записывает путь к файлу в `data/speaker-recordings.json`. Поля для отдельного файла/ссылки скачивания можно оставить пустыми: сайт использует основной аудиофайл и для плеера, и для кнопки «Скачать».

Если аудио хранится снаружи, используйте поле «Внешняя ссылка на аудио или путь».

Поддерживаемые расширения в CMS-конфигурации:

```text
mp3, m4a, wav, ogg
```

Для Cloudflare Pages один статический файл должен быть небольшим. Перед загрузкой больших записей проверьте актуальные лимиты Cloudflare Pages. Крупные аудиофайлы лучше хранить отдельно и указывать публичную ссылку на файл.

## Деплой на Cloudflare Pages

Рекомендуемый сценарий:

1. Создать приватный GitHub-репозиторий.
2. Положить файлы сайта в корень репозитория.
3. Подключить репозиторий в Cloudflare Pages.
4. Использовать настройки:
   - Build command: пусто
   - Build output directory: `/`
   - Build step: не требуется

Перед первым коммитом можно начать историю репозитория с нуля:

```bash
rm -rf .git
git init
git add .
git commit -m "Initial static DRA website"
```

## Служебные файлы

- `.pages.yml` — конфигурация Pages CMS
- `_headers` — HTTP-заголовки для Cloudflare Pages
- `.nojekyll` — отключение обработки Jekyll
- `robots.txt` — правила для поисковых роботов
- `sitemap.xml` — карта сайта
- `404.html` — страница ошибки 404

## Что не хранить в репозитории

Даже если репозиторий приватный, в нём не должны лежать:

- внутренние проектные документы и черновики
- история рабочих обсуждений
- инструкции для генерации или автоматической доработки кода
- backup/tmp/log-файлы
- неиспользуемые справочные документы
- `.git` внутри deploy-архива
- `node_modules`


## Шапка сайта

Пункты меню редактируются в `data/navigation.json` через раздел Pages CMS «Шапка и меню». HTML-страницы содержат только контейнер навигации; меню рендерится из JSON.
